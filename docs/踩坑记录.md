# 踩坑记录

本文件记录《鼠鼠大王工具箱》开发过程中踩过的坑与根因，供排查复用、避免重蹈覆辙。

**与《开发规范.md》的分工**：
- **开发规范**：必须遵守的规则（提交前置、i18n 走 zh.json、双主题同步、data/ 原子写等），回答"**怎么做**"；
- **踩坑记录**：真实遇到过的故障（现象 → 根因 → 解决），回答"**为什么这样做、别再踩**"。

按主题归类，每条自含现象与根因，不必依赖上下文即可独立查阅。

## Qt / 渲染

### QPainterPath::arcTo 并不是"真圆弧"
- 现象：想用 `arcTo` 替代逐点折线采样以大幅减少路径元素，误以为它是原生圆弧、Qt 会自动足够细分地平滑渲染。
- 根因：`QPainterPath` 的元素类型只有 moveTo / lineTo / cubicTo，`arcTo` 内部立即转成三次贝塞尔（每 90° 一个 cubic）；渲染时 QPainter 按约 0.25 逻辑单位的容差细分贝塞尔，小半径（3~4 单位）曲线放大后仍会折角。
- 解决：平滑与否取决于细分容差——要么 `QPainter::setTolerance()` 调小，要么按弦高误差自适应折线采样（见"算法与设计"节）。不要假设 "arcTo = 平滑"。

### DeviceCoordinateCache 导致贝塞尔放大后折角
- 现象：拼图碎片轮廓在视图放大后呈明显多边形感。
- 根因：`DeviceCoordinateCache` 在 item 局部小坐标系下栅格化贝塞尔，被 view 放大后轮廓折角。
- 解决：移除该缓存、直接渲染，让 QPainter 按设备精度 flatten 曲线。

### QImageReader.setScaledClipRect 对部分 PNG 输出全黑
- 现象：来源窗口缩略图全部黑框。
- 根因：该批 PNG 在 `setScaledClipRect` 缩放+裁剪解码路径下输出全黑（与图片元数据/Qt 解码实现相关）。
- 解决：改为缩放解码 + 手动中心裁剪；另建磁盘缩略图缓存（源文件 mtime 变化自动重生成），来源窗口秒开。

### offscreen 平台不渲染中文字形
- 现象：`QT_QPA_PLATFORM=offscreen` 下截图中的中文全是方块。
- 解决：截图探针断言避开中文文本（用图形/像素采样验证），文案正确性交给 i18n 测试。

### QPropertyAnimation 在 offscreen 下不自动推进
- 现象：测试里 `start()` 后动画不运行、`finished` 不触发。
- 根因：动画推进依赖事件循环，测试环境无事件循环。
- 解决：测试直接调用动画结束后的回调（如 `_after_snap`）模拟 finished，断言时序语义而非动画本身。

### QListWidget IconMode 布局行为不可控（卡片网格）
- 现象：每日密码卡片网格用 QListWidget IconMode + 手动 gridSize：Adjust 模式下自动列数与手动 gridSize 失配、Fixed 模式列数行为不可预期、`setSpacing` 不参与步进——纵向间距异常、拖拽窗口宽度时列数闪烁。
- 根因：Qt 该视图的布局步进是黑盒，尺寸/间距/列数三者无法同时精确控制。
- 解决：弃用 QListWidget，改 `QScrollArea + 自研 QLayout 流式布局`：间距编入布局步进（横/纵一致），列数 = 可用宽度的单调函数（从大到小选首个 clamp 后整行放得下的列数，且不超过卡片总数），卡片宽度在 [MIN, MAX] 内伸缩填满。行为确定、可数值验证。

### WA_DeleteOnClose 后访问 Python 包装抛 RuntimeError
- 现象：预览窗口 `close()` 后测试访问 `preview.isVisible()` 抛 `libshiboken: Internal C++ object already deleted`。
- 根因：`WA_DeleteOnClose` 在 close 时销毁 C++ 对象，Python 包装仍持有引用但底层已释放。
- 解决：判断窗口是否已关闭/销毁用 `shiboken6.isValid(obj)`；关闭后避免再访问其属性。

### 直接调用 mousePressEvent 绕过 eventFilter
- 现象：测试直接 `widget.mousePressEvent(ev)` 模拟点击，挂在该 widget 上的 eventFilter 不生效，窗口未关闭。
- 根因：eventFilter 在 Qt 事件分发路径（`QApplication.sendEvent → QObject.event`）执行；直接调方法绕过分发。
- 解决：模拟事件一律 `QApplication.sendEvent(widget, event)` 走真实分发；只有被测对象自身 override 的 `mousePressEvent` 才可直调。

## Windows 平台

### 原生标题栏不随主题实时变色
- 现象：切主题后标题栏颜色不变，失焦或缩放窗口后才变。
- 根因：DWM 不主动重绘非客户区；`SWP_FRAMECHANGED` / `RedrawWindow` / `DwmFlush` 均无效。
- 解决：唯一有效是发送 `WM_NCACTIVATE`（先反向后按真实激活状态重绘）。钩子函数调用顺序须断言（`[True, False, True]` 防回归）。

### 空窗口标题仍显示应用名
- 现象：`setWindowTitle("")` 后标题栏仍显示应用名。
- 根因：Windows 在标题为空时回退显示 `QApplication::applicationDisplayName`。
- 解决：`applicationDisplayName` 一并置空，标题栏才真正空白（`GetWindowTextW` 验证 `''`）。

### Pillow 生成 ICO 缺 256 尺寸
- 现象：生成的 `.ico` 只有 16/24/32/48/64/128，缺 256。
- 根因：Pillow 保存 ICO 要求主图先 resize 到 256，否则不写 256 项。
- 解决：居中裁方 → LANCZOS 放大 256 → 再保存多尺寸 ICO（16–256）。

### QGraphicsView 未布局时 fit_board 拿不到真实缩放
- 现象：`__init__` 里 `fit_board()` 后 `transform().m11()` 是默认值，不是"初始窗口"的真实缩放。
- 根因：窗口未显示时 viewport 尺寸非最终值，`fitInView` 按默认尺寸计算缩放；真实缩放发生在 showEvent/resizeEvent。
- 解决：首显 `showEvent` 后一次性重建路径（`QTimer.singleShot(0)` + 防重标志位），按真实缩放采样。

## Git 与工具链

### GitHub HTTPS 推送连接重置 / 空回复
- 现象：`git push` 报 `Connection was reset` 或 `Empty reply from server`；`git ls-remote`（读）正常。
- 根因：网络波动（写入大请求被中断），非代码或认证问题。
- 解决：`git config http.postBuffer 524288000` + `git -c http.version=HTTP/1.1 push`；仍失败则等待网络恢复后重试（本地提交不受影响）。用后还原临时配置。

### rebase 中途 vim 卡死
- 现象：rebase 需要编辑 commit message 时卡在 vim。
- 根因：PowerShell 新会话丢失 `GIT_EDITOR` 环境变量，编辑器回退默认 vim。
- 解决：先杀 vim 进程，再带 `GIT_EDITOR`（指向辅助脚本）重续 rebase；辅助脚本用完即删。

### `%` 格式化撞 ruff
- 现象：f-string 以外用 `%` 格式化被 ruff（UP 规则）报错。
- 解决：一律 f-string（已写入开发规范）。

### Windows 环境无 Bash / Edit 工具需先完整 Read
- 现象：git 等命令用 Bash 报"not available"；Edit 工具报"File has not been read yet"。
- 根因：Windows 主机须用 PowerShell 语法；Edit 工具要求目标文件在本会话被**完整** Read 过（部分/分段读取不算）。
- 解决：shell 一律用 PowerShell；编辑前整文件 Read。

## 数据与测试

### 测试污染真实 data/settings.json
- 现象：某次测试把真实设置文件的主题误改成 light。
- 根因：测试直接走了默认路径写 `data/`。
- 解决：`data/` 读写一律 `tmp_path` + `monkeypatch` 隔离（已写入开发规范，教训保留）。

### 持久化写回覆盖手改字段
- 现象：用户在配置文件中手改的字段，主题/语言变更后被覆盖丢失。
- 根因：写回函数只保存固定字段集合（如 `{"theme", "language"}`）。
- 解决：写回前先读回现有文件再合并更新（load → update → save），保留全部已知字段（参考 `app.py` 的 `_persist`）。

## 算法与设计

### 固定角度圆弧采样：低缩放浪费、高缩放不够
- 现象：固定 2° 采样在低缩放时大量采样点落在同一像素内（纯浪费），高缩放时又可能不够平滑。
- 根因：按角度等分与渲染分辨率无关。
- 解决：按弦高误差目标自适应：`Δθ ≈ √(8ε/(r·scale·dpr))`，ε 为目标设备像素误差（0.5px，动画可 0.25px），段数 clamp [4, 120]。典型场景点数减少 10~17 倍。

### 网格按短边 target_cell 计算导致碎片数波动
- 现象：不同宽高比图片碎片数差异大，难度不一致。
- 根因：行数由短边决定、列数随宽高比放大，碎片数 ≈ 面积/cell²，随图变化。
- 解决：按目标碎片总数求解：正方形 cell + floor 取整下直接解 `c0=√(面积/T)` 并邻域微调。**不要加 `cols ≤ 2×rows` 之类与宽高比必然矛盾的约束**（宽高比 ≥2 时恒失败会死循环）；超宽图由 cell 下限兜底即可。

### 全量完成判定 → 增量集合
- 现象：每释放一块就全量扫描全部碎片偏移总和（O(n)）。
- 解决：以"已吸附集合"为唯一事实源（拿起 discard、释放 add），完成判定 = 集合大小 == 总数（O(1)）+ 吸附动画结束后一次全量确认。集合幂等，天然无计数漂移，比整数计数器更稳（不担心"计数 bug 卡死"）。

## 外部数据源

### 依赖外部数据源的展示顺序不稳定
- 现象：同一批地图数据，tmini 返回顺序 AZ3 在最前、shushu.fan 在最后，卡片顺序随源变化跳动。
- 根因：渲染直接遍历源返回的 dict 顺序。
- 解决：展示顺序显式固定（`MAP_ORDER`），源命名归一化（`AZ3核电站` → `AZ3`）后按固定顺序取图；源返回顺序不参与展示排序。

### 上游限频 + 更新滞后 → 循环请求打满
- 现象：tmini 接口限频 10 次/分钟（超限返回 `{"code":219}`）；凌晨源更新滞后会返回"昨日"数据，页面每分钟跨日检查反复请求打满限频。
- 根因：当日缓存未生效时每次检查都重新拉取；拿到非今日数据又立即重试。
- 解决：当日缓存直接渲染不请求；源返回非今日数据视为"源未更新"，延后 15 分钟再试；全部失败同样节流；手动刷新按钮例外（用户主动操作）。
