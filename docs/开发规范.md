# 开发规范

本文件面向《鼠鼠大王工具箱》的开发者，描述项目开发中需遵守的规则。新改动前请先通读，提交前对照检查。

## 项目与运行环境

- 对外统一名称：**《鼠鼠大王工具箱》**。文档、界面与构建产物名（exe）一律使用此名称；`deltaforcebox`、`DeltaForceBox` 仅作 Python 包名、仓库目录、spec 文件名等内部技术标识符保留。**例外**：安装器产物文件名统一英文 `DeltaForceBox-Setup-Beta-<版本>.exe`（中文文件名不便作为 GitHub Release 资产上传）；**默认安装目录统一英文 `D:\Program Files\DeltaForceBox`**（仅对后续版本生效，Beta-4.2 及更早保持旧默认 `{autopf}\鼠鼠大王工具箱`），安装后的显示名不受影响
- Python ≥ 3.12 + PySide6（Qt6），源码位于 `src/deltaforcebox/`
- 依赖与开发工具经 `pyproject.toml` 管理，虚拟环境 `.venv/`
- GUI 测试在 offscreen 平台运行（`QT_QPA_PLATFORM=offscreen`），不弹出真实窗口
- 常用命令（在项目根目录）：
  - 测试：`.\.venv\Scripts\python.exe -m pytest -q tests`
  - 代码检查：`.\.venv\Scripts\ruff.exe check src tests`

## 代码风格

- 新代码遵循 ruff 规则（`E/F/W/I/UP`，行宽 100），提交前必须 `ruff check src tests` 无告警
- 字符串格式化一律使用 f-string，禁止 `%` 格式化
- 新文件/函数尽量带类型标注，模块统一 `from __future__ import annotations`
- 导入顺序遵循 isort 规则：标准库 → 第三方 → 项目内，同类内按字母序

## 国际化（i18n）

- **所有面向用户的文案必须走 `resources/i18n/zh.json` 的 key，禁止在代码中硬编码中文**（测试断言除外）
- 当前仅支持中文：`SUPPORTED_LANGUAGES = ("zh",)`，不新增英文支持
- 带参数的文案用 `%1` 占位符（如 `"puzzle.sources.count": "共 %1 张图片"`）
- 新增 key 后运行 `test_i18n_chinese_only`，该测试自动对照 zh.json 全量校验
- **用户输入的内容**（如我的改枪码的命名 / 描述 / 改枪码）属于用户数据，写入 `data/`，**禁止**写入 i18n 文件；i18n 只承载程序固定文案

## 主题（明暗双主题）

- 新增控件的任何样式必须**同时写入 `dark.qss` 与 `light.qss`**，只改一套视为缺漏
- 颜色需在两套主题下都可读；链接色统一用中性蓝 `#4d8ff7`
- 新增窗口必须适配主题：背景（QDialog 基础规则）、滚动条、控件样式都要有对应规则
- 新窗口默认非模态（`show()` 而非 `exec()`），不阻塞主窗口

## 数据持久化

- 用户数据一律写入 `data/` 目录（已被 `.gitignore` 忽略），**禁止提交用户数据进仓库**
- 页面级用户数据（如 `data/my_gun_codes.json`）遵循 `core/` 模块模式：独立模块提供 load / save（原子写）/ id 生成，load 容忍缺失与损坏回退安全值（参考 `core/my_codes.py`）
- JSON 写入使用原子替换：先写 `.tmp` 临时文件，再 `os.replace`，避免写一半损坏
- 读取必须容忍文件缺失/损坏，回退到安全默认值（参考 `core/records.py`、`core/settings.py`）
- 缓存/存档反序列化使用**字段白名单**逐条构造（参考 `gun_code_page._solution_from_dict`）：旧版本多/缺字段或类型异常只跳过该条，禁止 `Model(**raw)` 整体失败导致整页空白

## 网络与外部数据源

- 外部网络请求一律在后台线程（QThread）执行，UI 只在主线程更新（参考 `daily_password.py` / `daily_password_page.py`）
- 调用有频率限制的第三方接口前必须设计缓存与节流：当日缓存直接复用、失败延后重试、手动刷新例外，禁止循环请求打满上游限频
- 多数据源场景必须定义优先级顺序（首选可配置），主源失败自动回退备用；全部失败回退旧缓存并在界面提示
- 解析结果统一转为内部数据结构（如 `DailyPasswordData`），页面不直接接触网络原始格式
- 静态展示类数据（地图名、位置描述、缩略图）优先内置本地资源，减少对数据源的运行时依赖
- 依赖外部数据的展示顺序必须显式固定（如 `MAP_ORDER`），不得依赖源返回顺序；源命名变体统一归一化后再匹配
- 分页接口同步：页数以响应中的 `totalCount` 动态计算（**不硬编码页数**），`totalCount` 缺失时以"空页"为结束信号；页间加间隔（如 300ms）防压力；同步须支持中断并保留已收集数据（参考 `gun_solutions.sync_official_solutions`）
- 外部数据去重：以稳定唯一 id 幂等（首条保留），**合并层 + 保存层双层去重**；缓存采用整体替换（快照语义）而非增量合并，已下架数据随下次同步自动消失（参考 `_merge_official` / `save_guns_cache`）
- 图片资源分层缓存：磁盘持久（存在即跳过下载、原子写）+ 内存 LRU（QPixmapCache，容量配置化，如 `image_cache_limit_mb`）+ 渲染懒加载（只对当前可见项）
- 页面级后台线程必须提供 `_shutdown()`（requestInterruption + wait 限时等待），由 `MainWindow.closeEvent` 统一遍历调用（`getattr(page, "_shutdown")` 兜底），防止 QThread 运行时被回收硬崩溃；长循环拉取须支持 `should_stop` 回调（如 `fetch_password(..., should_stop=...)`），中断后快速退出
- 图片/文件下载线程必须**串行化**：worker 运行中到达的新任务并入待办、结束后再启动，防止多个 worker 并发写同一 `.tmp` 路径导致缓存损坏；worker finished 回调校验身份（`self._image_worker is worker`）后再置空，窗口关闭（`_closing`）后禁止再启动新 worker

## 配置项

- 新增配置项必须登记进 `core/settings.py` 的 `DEFAULT_SETTINGS`（白名单加载，缺失自动补默认值）
- 命名：蛇形全小写（如 `puzzle_pieces`）
- **写回必须保留手改字段**：主题/语言变更持久化时先读回现有文件再合并更新，禁止只写固定字段集合覆盖掉用户在配置文件中手改的内容（参考 `app.py` 的 `_persist`）
- "仅配置文件修改"的配置项：**不加设置界面控件**，但消费侧必须做边界归一化（非法/越界回退到安全值，参考 `puzzle_page.py` 的 `_normalize_piece_count`），并配套测试
- 隐藏配置的整型消费**统一走 `core/settings.safe_int(value, default, lo, hi)`**：非数字回退默认、越界 clamp；禁止直接 `int(config.get(...))`（用户手改任意内容都会导致启动崩溃）

## 测试规范

- 每个新功能必须配套 pytest 回归测试；修复 bug 须加防回归测试
- 涉及 `data/` 读写时用 `tmp_path` + `monkeypatch` 隔离，**禁止污染真实 data/**（历史上曾误改真实设置文件，教训保留）
- 依赖 Qt **全局共享资源**（如 QPixmapCache、全局 cacheLimit）的测试必须**自给自足**：开头显式设回所需状态并清理，防止其他用例（如把上限设为 0 的用例）静默污染后续断言
- 功能完成后先跑全量测试再提交：`pytest 全绿 + ruff 无告警` 是提交前置条件

## 性能与验证

- 性能类改动必须附带**可复核的验证手段**（渲染探针截图、点数/复杂度断言、基准对比），仅凭主观"更流畅"不算完成
- 改动前先量化现状（如路径元素数、单次判定复杂度），改动后给出对比数据
- 性能改动同样要过全量回归，防止几何/时序语义被破坏（如自适应采样不得破坏拼图咬合互补）
- 大列表渲染用**翻页**（任何时刻只实例化当前页）控制内存峰值，页大小配置化；销毁卡片用 `shiboken6.delete` 立即删除，不用 `deleteLater`（退出时 DeferredDelete 与 Python GC 双重删除会崩溃）

## Git 提交

- message 格式：`类型: 中文描述`；类型取值 `feat`（功能）/ `fix`（修复）/ `style`（样式）/ `docs`（文档）/ `chore`（杂项）/ `refactor`（重构）/ `test`（测试）
- 一个功能一个提交，完成后立即提交；提交前确认工作区只包含本次改动
- 改动历史整理（squash 合并）须先与用户确认，合并后必须重跑全量测试验证内容一致

## 版本管理

- **版本号的唯一来源**：`src/deltaforcebox/__init__.py` 的 `__version__`（如 `"Beta-1.1"`）
- 发布新版本（源码）三步：
  1. 修改 `__version__`（如 `"Beta-1.1"`）
  2. 同步 `pyproject.toml` 的 `version` 字段
  3. 在 `docs/版本日志.md` 顶部追加新版本节（格式：`## 版本号（日期）` + `### ` 分组 + `- ` 条目）
- 首页"版本"与"最近更新"自动从 `__version__` 与版本日志读取展示，无需额外改动
- **发布发行版（打包）时，额外同步以下版本位置**：
  4. `scripts/version_info.txt`：`FileVersion` / `ProductVersion` 及 `filevers` / `prodvers` 随 `__version__` 更新（exe 文件属性）
  5. `scripts/installer.iss`：`MyAppVersion` / `MyAppDisplayVersion` / `OutputBaseFilename`（安装器产物名，统一英文 `DeltaForceBox-Setup-Beta-<版本>`）随版本更新；`scripts/build_installer.ps1` 的产物提示文本同步
- 版本更新后按 `scripts/build_dist.ps1` → `scripts/build_installer.ps1` 顺序重建发行版与安装器，并用 `scripts/verify_dist.py` 验证产物完整
- **所有面向用户显示的版本描述必须统一**（如 `Beta-1.1`），不得出现多处不同写法

## 界面与交互约定

- 界面语言一律中文，不使用 emoji
- 用户可见文案保持与文档（版本日志）一致的版本描述
- 新增功能入口优先考虑侧边栏分组结构（首页 / 分组 / 设置），分组可折叠
- 窗口标题栏文本保持隐藏，品牌名只在侧栏顶部展示
- 分页条显示规则（参考 `gun_code_page._pager_items`）：总页数 ≤ 7 全部显示；否则固定首尾页 + 当前页前后各 2 页；间隙用可点击省略号（跳 ±5 并收敛边界）；当前页以 objectName 区分高亮，双主题同步
- 下拉框宽度按候选项最长文本动态设定（`fontMetrics().horizontalAdvance` 量宽 + 边距余量），确保收起状态完整显示全部文字；选项重建时自动重算
- 筛选下拉统一使用 `widgets/search_combo.py` 的 `SearchCombo`：editable + NoInsert（输入不固化进候选）+ QCompleter 包含匹配 + 输入即筛选；筛选条件一律以 `filter_text()` 为准（空白或「全部」文本视为无条件），禁止直接读 `currentData()`（手动输入时无效）
- 自动更新约定：版本号唯一来源 `__version__` 与 git tag、GitHub Release 保持一致；**每个定版必须创建 GitHub Release 并附带安装包资产**（`DeltaForceBox-Setup-Beta-<版本>.exe`），否则自动更新（按语义版本取远端最高）无法发现该版本、或提示“暂无可下载安装包”；升级正式版时 `__version__` 与 tag 同步切换为 `v-X.Y`（解析器已兼容 Beta→正式）
- 远端版本检查必须过滤 `draft` / `prerelease` 的 Release（草稿/预发布 tag 可能高于正式发布，被选中会提示“暂无可下载安装包”）；Release 资产字段同样做类型归一化（`size` 非数字回退 0）
- 面向用户的提示一律使用首页右上角提示条（非弹窗），不新增弹窗
- 我的改枪码表单：枪械名称 / 武器类型由改枪码自动解析带出（`parse_gun_code` 首段 + `build_gun_weapon_map` 从属映射），字段只读展示、不提供手动输入；映射未命中时类型留空（卡片 meta 自动省略空段）
- SearchCombo 交互约定：点击输入框 = 清空输入 + 展开全量候选（editable 下拉点击输入框区域事件被 lineEdit 消费，须经 `installEventFilter` 拦截 MouseButtonPress / FocusIn / FocusOut）；非焦点且无条件时显示「全部」提示文本，聚焦时清空准备输入；候选顶部固定「全部」文本项（`itemData` 为空，内部无条件），`reset()` 与初始 `set_items(preserve=False)` 均回到「全部」提示态
- 配置管理约定：设置界面可见项写入 `data/settings.json`（key 限 `DEFAULT_SETTINGS`，`save_settings` 只写这些 key）；不进设置界面的隐藏配置写入 `resources/config/app_config.json`（key 限 `DEFAULT_APP_CONFIG`，随资源分发可手改）；两者职责不混用，新增配置项先判定归属

## 安全与防御

- 不把密钥、账号、真实用户数据写入代码或文档
- 运行时路径一律经 `core/paths.py` 定位，不依赖当前工作目录
- 修改或删除文件前先确认归属（用户文件 vs 程序生成），不擅自移动/重命名用户文件
- 外部数据（昵称、标题等）用作文件名时必须 **sanitize**：Windows 非法字符 `<>:"/\|?*` 与控制字符替换为 `_`、去尾随点/空白（参考 `gun_solutions._safe_filename`），否则写盘失败或落入嵌套子目录
